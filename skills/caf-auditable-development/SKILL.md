## Use the Caf loop to leave useful evidence without making temporary work permanent

When development needs later review, recovery, reproducibility, or coordinated agents, suggest the caf-auditable-development skill in chat and explain the useful next step. State the requested outcome, current task owner, selected intent or policy, proposed scope, and decisive evidence in plain English. Keep this proportional: a read-only answer needs its sources, and a small fix usually needs the existing task, contract, diff, and focused result. Discovery suggests the skill; it does not activate policy or authorize effects. Recognize the need from the conversation; do not require the user to know a skill name. When chat reveals a repeated useful development method, search existing skills and their CML owners, suggest the closest fit, and explain the match. If a real gap remains and creating a skill is in scope, register the smallest reusable guidance through SkillPackage and explicit AgentSpec selection, then generate its native projection. Keep one-off or speculative work temporary instead of registering every experiment.

Reuse the existing Caf loop: orient to the request and current authorities, inspect current implementation and ownership, propose the smallest change, preflight its boundaries, execute authorized work, observe results, route acceptance, and retain useful evidence. Confirm the work is still needed before claiming it. Inspect accepted module interfaces and CML before inventing glue. Reuse an existing CML contract for an ordinary fix. If meaning is missing, author a bounded proposal in the narrowest existing owner and validate it before implementation; keep unresolved acceptance explicit. Do not create a second loop, universal audit-log schema, orchestration engine, task database, or mandatory planning document.

Choose temporary tasks, scripts, worktrees, and agent assignments just in time. Use parallel agents only when authorized and independent ownership or review makes total work cheaper or safer. Before delegation, name the owner, exact input refs and revisions, permitted scope and effects, expected output and evidence, integration owner, and stopping or recovery condition. Keep competing writers isolated. Record actual agent handles and returned artifacts with the existing task when needed for recovery. A plan to delegate is not evidence that an agent ran, and a returned answer is not independent acceptance. Promote a repeated method into reusable CML only after it proves useful.

Keep one concise audit trail in the existing task and linked native artifacts. Record material decisions and their user-visible reasons, exact source revisions or digests, selected policy and skill identities, requested versus observed model or effort when available, relevant tool versions, commands and inputs, output locations and digests, verification, corrections, blockers, and the next owner. Mark unknown observations as unknown. Use an available show-me-your-work skill for a detailed local decision trail only when the run warrants it; link that trail from Beads instead of copying task state. Without that helper, a short evidence-linked task comment is sufficient. Never collect hidden reasoning, unrestricted transcripts, secrets, or unrelated personal data; retain only the evidence needed under its existing access and retention rules.

Distinguish reproducibility from auditability. A reproducible deterministic step has exact inputs, source and tool versions, selected configuration, a rerun command, and an output comparison. An adaptive model or human decision is auditable when its admitted inputs, concise decision, observable result, and disposition can be inspected; identical model output is not promised. Preserve native observations separately from authored expectations. Do not label a generated summary, passing check, process exit, or proposed receipt as observed effect completion or owner acceptance.

Verify meaningful behavior against an independently stated expectation. Inspect generated output and prove one actual path when claiming runtime support. Report the achieved stage precisely: CML-described intent, generated guidance, selected delivery, observed execution, and accepted result are different claims. A client that can read SKILL.md can use the guidance through its native workflow; this does not prove a Caf adapter, automatic activation, enforcement, or agent compliance. Keep direct native commands usable when Caf integration is unavailable and report the missing capability. Compare Caf's authoring, coordination, verification, runtime, and recovery cost with that honest native route; remove layers that add no useful value.

At a meaningful checkpoint, make chat sufficient to understand what happened: name the result, exact evidence, limits, remaining owner, and next action. Keep task-local evidence in Beads, stable semantics in their CML owner, source history in Git, and native events or receipts in their existing evidence owner. Commit and finish only the authorized scope under repository gates. Remove only owned disposable artifacts after checking for unique work. Hand off exact inputs and unresolved work so another agent can continue without reconstructing the conversation.

Reason: Typed intent and linked observations make work reviewable across agents while preserving cheap temporary experiments and each authority's existing role.

Examples:
- A model proposes a design from pinned inputs. Record the proposal, test evidence, and owner disposition as an auditable decision; do not claim deterministic model replay.
- A one-off script compares two generated files. Its command, inputs, result, and removal condition are enough; no reusable workflow or new CML schema is needed.
- A worker fixes an isolated bug while a reviewer checks an independently stated behavior. The task links both revisions and results; integration verifies the combined change before closure.

Limits:
- No autonomous acceptance, permission expansion, automatic skill activation, hidden reasoning capture, permanent record of every command, or requirement to create agents.
- No claim of live Codex, Claude, Pi, or other client execution from a generated file, successful schema check, or projection fixture.
