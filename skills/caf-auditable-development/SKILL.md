## Use the Caf loop to leave useful evidence without making temporary work permanent

Choose temporary tasks, scripts, worktrees, and agent assignments just in time. Use parallel agents only when authorized and independent ownership or review makes total work cheaper or safer. Before delegation, name the owner, exact input refs and revisions, permitted scope and effects, expected output and evidence, integration owner, and stopping or recovery condition. Keep competing writers isolated. Record actual agent handles and returned artifacts with the existing task when needed for recovery. A plan to delegate is not evidence that an agent ran, and a returned answer is not independent acceptance. Promote a repeated method into reusable CML only after it proves useful.

Keep one concise audit trail in the existing task and linked native artifacts. Record material decisions and their user-visible reasons, exact source revisions or digests, selected policy and skill identities, requested versus observed model or effort when available, relevant tool versions, commands and inputs, output locations and digests, verification, corrections, blockers, and the next owner. Mark unknown observations as unknown. Use an available show-me-your-work skill for a detailed local decision trail only when the run warrants it; link that trail from Beads instead of copying task state. Without that helper, a short evidence-linked task comment is sufficient. Never collect hidden reasoning, unrestricted transcripts, secrets, or unrelated personal data; retain only the evidence needed under its existing access and retention rules.

Distinguish reproducibility from auditability. A reproducible deterministic step has exact inputs, source and tool versions, selected configuration, a rerun command, and an output comparison. An adaptive model or human decision is auditable when its admitted inputs, concise decision, observable result, and disposition can be inspected; identical model output is not promised. Preserve native observations separately from authored expectations. At a meaningful checkpoint, make chat sufficient to understand what happened: name the result, exact evidence, limits, remaining owner, and next action. Reason: Typed intent and linked observations make work reviewable across agents while preserving cheap temporary experiments and each authority's existing role.

Examples:
- A model proposes a design from pinned inputs. Record the proposal, test evidence, and owner disposition as an auditable decision; do not claim deterministic model replay.
- A one-off script compares two generated files. Its command, inputs, result, and removal condition are enough; no reusable workflow or new CML schema is needed.
- A repeated build-and-check process belongs in existing verification or workflow CML. Typed Haxe owns its algorithms and adapters; native reports own measurements and results. An optional AgentSpec-backed skill explains how an agent chooses and uses that process. The graph links those distinct owners. A shared data-shape constraint remains with its schema owner.
- A worker fixes an isolated bug while a reviewer checks an independently stated behavior. The task links both revisions and results; integration verifies the combined change before closure.
